# NodePhell 0.3.0

Released 2026-11-27.

This version makes it easier to start with an unfamiliar Python project and
to manage the runtimes and packages already on your machine.

## Discover dependencies

Run `nodephell discover` in a project that has no dependency metadata. It reads
Python imports and walks you through reviewing package names and version
constraints before writing `pyproject.toml`. It does not execute project code,
download packages, or synchronize automatically. Static imports are a starting
point; optional features, dynamic imports, and compatible versions still need
your review.

Existing project metadata is report-only. Requirements files can be selected
as synchronization inputs instead of reconstructing their dependency lists.

Import aliases and application hints are stored in
`assets/import-mappings.toml`. They can be edited without changing Python
source, or extended with `--mappings FILE`. Same-name imports use their own
names as suggestions. Application-specific hints require the relevant host
declaration or `--application NAME`.

## Manage installed files and registrations

Run `nodephell manage` to browse runtimes, packages, projects, and embedded
hosts, including registrations whose files have gone missing. The main menu
shows the management Python's version and executable path.

- Packages appear by name first, with their versions and builds inside.
- Left and right arrows change pages immediately; letters jump to matching
  names. Type a number and press Enter to select; Enter alone goes back.
- Colored choices and indented, wrapped paths make long inventories easier
  to read. `NO_COLOR`, dumb terminals, and redirected output disable color.
- You can unregister missing builds, remove unused managed files, or choose
  explicit integrity checks and cleanup. Each modifying action previews its
  targets and asks for confirmation.

Browsing does not hash every installed package file. Removal checks references
again before deleting files; selected unused-release removal protects referenced
releases even when damaged. Explicit store cleanup retains its existing
behavior for damaged entries, which affected projects can restore with
`nodephell install`. Individual CLI commands remain available.

## Install from source

```sh
git clone https://github.com/JustTryingToGetSomeWorkDone/NodePhell.git
cd NodePhell
./bin/nodephell launcher install
nodephell --version
```

NodePhell requires Python 3.11 or newer. Keep the checkout: installed commands
run its source directly. To update an existing checkout, run `git pull --ff-only`
there and rerun `./bin/nodephell launcher install`.

The optional FreeCAD adapter keeps its independent version. Install it from
the checkout with `nodephell plugin add ./plugins/freecad`.

## Validation

All 257 unit tests passed during release preparation. The launcher and project
metadata both report `0.3.0`, and the patch passes `git diff --check`.
The automated checks cover discovery, mapping overrides, maintenance safeguards,
package browsing, keyboard input, and terminal restoration.

The user confirmed JPG_to_PDF works after `nodephell discover` generated its
`pyproject.toml` and `nodephell sync` installed from that declaration. The local
lock selects CPython 3.12.15 and Pillow 13.0.0. This confirms the complete
discovery-to-sync workflow for this small project.

Earlier real-project validation includes PCB Timelapse rendering through KiCad
and ACE-Step ROCm music generation. These are recorded separately in the
[project compatibility ledger](../project-compatibility.md), alongside the new
JPG_to_PDF discovery result.
